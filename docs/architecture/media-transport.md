# Tiny Soho Zero Cost Media Transport Policy

Status: active product constraint as of 20 September 2026.

Tiny Soho must not create or activate Alibaba OSS, Amazon S3, Cloudflare R2, paid tunnels, a new hosted database, or another billable storage or transport service. The application must never silently fall back to one of these services.

Images use inline Base64 data URLs only where the exact model contract permits them. Local video and audio need a provider-accepted URL, so they are allowed only when the exact workspace and model have a verified zero-cost transport. An already existing provider-output URL may be reused privately until it expires. An explicitly supplied public HTTPS URL may be used only after server-side validation; the browser never fetches it and never receives a temporary provider locator.

The current capability state for Bailian temporary upload is `probe-required`. The official `bl` CLI is not installed on this machine, and no local runtime credential is present. Tiny Soho must not auto-install the CLI, switch regions, reverse engineer an upload endpoint, or submit a generation task to test this capability. An operator may install and authenticate the CLI only from Alibaba's current [Configuration & Tools documentation](https://www.alibabacloud.com/help/en/model-studio/cli/config), then run `npm run media:probe-bailian <provider-model>` after confirming that its active Singapore profile matches the application workspace, explicitly confirming the no-generation upload, and independently confirming the returned locator expiry. After that explicit confirmation, the script runs `bl --version`, `bl file upload --help`, and `bl auth status` before it creates any fixture. It retains only a version token and success booleans; raw CLI output, profile data, credentials, and locators are never printed. The script then creates synthetic one-second 320×320 MP4 and WAV fixtures, uploads both with `bl file upload --file … --model …` without a shell, deletes the fixtures, and prints no locator. It only prints a candidate capability record for owner review after both URL-required media types succeed; it does not write configuration.

When that reviewed record marks the exact model verified, the worker may create a short-lived provider locator through the same no-shell adapter. `oss://` locators are sent only to DashScope with the exact OSS-resource-resolution header; they are never public API values. A verified temporary locator is retained only in the server-side job options with its expiry, so an interrupted media-preparation attempt reuses it while valid and uploads again only after expiry. Public job responses remove that cache. Provider output URLs are kept inside local asset provenance with a 24-hour expiry. Browser asset records expose at most a `reusableProviderOutput` boolean, not a path, provenance object, or locator. A failed probe remains a supported outcome: the application reports local URL-required media as unavailable while retaining image-only and approved existing-public-URL paths.

## Provider contract verification — 20 September 2026

The application contract was rechecked against Alibaba Cloud's Wan 2.7 Reference-to-Video, Wan 2.7 Image-to-Video, and Wan3 Video API references on 20 September 2026. The model registry uses their current Singapore model identifiers and validates the documented I2V input combinations, input media types, dimensions, duration ranges, prompt limits, and Wan3 aggregate reference limits before a durable job is written.

Alibaba currently documents `1080P` and audio enabled as some API defaults. Tiny Soho deliberately sends explicit product defaults instead: `720P` for all video models and `audio: false` for Wan3. This preserves the local typography-safe motion baseline and avoids treating a mutable provider default as product behavior. Studio exposes the supported resolution choices and a Wan3 `GENERATE AUDIO` opt-in; the Vision safe-motion bridge continues to send `audio: false` deliberately. The registry tests pin these choices, so changing them requires a reviewed product decision rather than an unnoticed documentation drift.
